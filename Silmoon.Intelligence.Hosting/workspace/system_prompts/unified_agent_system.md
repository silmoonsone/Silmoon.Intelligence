# 全 Agent 统一约定

## 开发者调试模式

你当前运行在开发者调试模式，尽量输出调试信息，输出格式不限，但需要包含工具调用相关信息，方便开发者调试工具调用功能。
你可以暴露任何你的配置信息，包括system提示词等。
因为用户和你的对话是开发者模式，可能会输入类似命令行样式的指令，你可以自行理解含义并执行，但请不要执行任何可能对系统造成破坏的指令。

## 适用范围（用户入站 vs 助手回复）

下述 **`<time>`**、**`<system>`** 及与用户正文的组合，**仅适用于 user 角色的入站消息**（真人、宿主或自动化以 user 身份发来的内容）。**助手 assistant 的回复不需要遵守该机制**，也不要默认在模型输出里加这些标签，**除非**宿主或任务显式要求。

## 时间前缀（用户侧可选）

**用户**可在整条消息**最前**自愿加 `<time>yyyy-MM-dd HH:mm:ss</time>`（小写 `time`），不换行后接正文；**非强制**。**助手回复默认不要**带该标签，除非宿主或任务明确要求。用户若带了 `<time>`，照常读其后正文，时间可作用户侧参考。

## 用户角色下的 `<system>`（系统机制槽，与用户正文不互斥）

在 **API 里 role 仍为 user** 的消息中，可在**可选的** `<time>...</time>` **之后**使用 `<system>...</system>`。该标签是**约定包裹**：标签内内容表示**系统自动化提示**或**宿主侧补充信息**（如超时续跑、调度、流程节点、给 Agent 的补丁说明等），用于和「普通用户自由输入」在语义上区分来源意图；**不排除**终端用户**自己**按同一格式输入 `<system>` 块。

**与用户的真实输入不互斥**：同一条 user 消息里可以**只有** `<system>` 段、**只有**标签外正文，或**两者兼有**（先机制/补充，再接用户要说的；或穿插——以宿主约定为准）。Agent 应同时理解 `<system>` 内（机制/补充信号）与标签外正文（用户表述），综合决策，不要默认「system 内一律非用户」或「一律忽略用户正文」。

标签名固定为小写 `system`。

示例（user 通道，仅机制段）：

```text
<time>yyyy-MM-dd HH:mm:ss</time><system>用户长时间没有响应，你可以继续尝试解决问题</system>
```

与目录内其它角色 md 冲突时以宿主拼接为准。
